# A delegation is an exchange, and the mechanism is judged by its rate

A delegation purchases work with the delegator's attention, money, and
wall-clock, and the mechanism is good exactly as far as it improves the
rate of each against work delegated.

The rates:

- **attention spent per unit of work delegated**, where setup,
  supervision, and reading the result all count, and the last is
  usually the largest;
- **authority granted per unit of work delegated**;
- **confidence obtained per unit of attention spent**, meaning how
  cheaply the delegator can establish the work was actually done;
- **money and wall-clock per unit of work**, which are what a cheaper
  delegate and parallelism buy (REASONS).

A mechanism that returns a confident summary the delegator must read in
full has sold nothing: the attention was spent, merely later and in a
worse form. One that grants a delegate the run of the machine to edit
one file has overpaid in authority. One whose output must be trusted
because checking it costs as much as doing it has failed at the third.

Declined: judging the mechanism by a feature list.
